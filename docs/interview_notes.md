# 面试话术：零人工标注的自动化红队数据集

## 与三个项目的对照（四句话）

1. **学 Claudini**——"Claudini 用随机 token 序列把数据集问题转化成优化问题；
   我学它把 dynamic 轨迹的判定也自动化——judge 结果就是标签，不人工标。
   不同的是它要白盒梯度，我的变异搜索在语义层，商用模型黑盒可用。"

2. **学 JBF（living benchmark）**——"JBF 的数据集是活的，我的策略库也是——
   dynamic 发现的新手法自动入库（`dynamic_traces.jsonl` 追加模式），
   数据集随使用生长；每周增量超阈值自动打包新版本（`version_dataset.py`），
   旧版本目录保留可复现。"

3. **学 ARMs（生成即标注）**——"ARMs 是生成即标注，我的 dynamic 轨迹也是——
   标签是判定的副产品，不是人工的后补。220 条旧数据用 funnel 多票制自动重判，
   三票分歧的 20 条标低置信降权、不占 ASR 分母，而不是硬标。"

4. **工程替代人工的总原则**——"人工标注跟不上攻击方法的演化速度。
   零人工不是偷懒：旧数据自动化重判（rejudge_multiturn）、开源集采信官方标签
   （SafeDialBench/CoSafe/MHJ）、新数据生成即标注（harvest_dynamic_traces）、
   质量用版本化追踪（living benchmark）而不是人工审核兜底。"

## 数据集三层结构（讲架构时用）

```
静态种子（attacks.jsonl 531 条）   → 回归基线，变异算子谱系
开源集（JBB + SafeDialBench + CoSafe）→ 广度，官方标签零人工
dynamic 轨迹（dynamic_traces.jsonl）→ 差异化，策略库数据源，自动生长
```

## 预判追问

- **"零人工标注质量怎么保证？"** → 三票制 + 置信度分层 + 低置信降权不占分母；
  防 reward hacking 靠入库门禁（策略 pending→approved 人工/复核闸）
- **"标签错了怎么办？"** → 每条带 judge_votes 溯源（三个裁判各投了什么），
  任何标签可重放；版本化目录可回滚
- **"和 PAIR 的区别？"** → "PAIR 是单会话迭代，我的策略库是跨会话学习——
  前者会打，后者越打越聪明"
- **"裁判会被幻觉骗吗？"** → "SkillAttack 证明没有轨迹验证的裁判会被幻觉执行
  骗过——我的判定输入是响应+工具调用轨迹，幻觉执行单独一类防御签名"
